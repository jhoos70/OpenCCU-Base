# Module: .github (ci_workflows)

## Overview

- Path: `.github/` (2 files, 331 lines total, both YAML under `.github/workflows/`)
- Language: YAML (GitHub Actions workflow syntax) with embedded Bash
- Role: CI/CD automation for OpenCCU-Base. One workflow builds and verifies the CMake package for four target architectures; the other regenerates the prebuilt `libXmlRpc.so`/`libxmlparser.so` binaries and opens a pull request.
- Not present: `CODEOWNERS`, issue/PR templates, `dependabot.yml`, composite actions, reusable workflows, `actions/` folder, release/deploy workflows (`ls -a .github` shows only `workflows`).
- Both files carry `# yamllint disable rule:truthy` (`ci.yml:2`, `update-prebuilt-libraries.yml:6`), so a yamllint config is presumably used, but none is in `.github/`.

## ci.yml

### Job `build` (`ci.yml:22-159`)
- Runner `ubuntu-24.04`, `timeout-minutes: 90` (`:24-25`), `fail-fast: false` (`:28`).
- Matrix (`:29-46`), 4 entries with keys `platform`, `debian_arch`, `multiarch_triplet`, `binary_format`:

| platform | debian_arch | multiarch_triplet | binary_format (matched against `file` output) |
|---|---|---|---|
| `x86_64-linux-gnu` | `amd64` | `x86_64-linux-gnu` | `x86-64` |
| `aarch64-linux-gnu` | `arm64` | `aarch64-linux-gnu` | `ARM aarch64` |
| `arm-linux-gnueabihf` | `armhf` | `arm-linux-gnueabihf` | `ARM` |
| `i686-linux-gnu` | `i386` | `i386-linux-gnu` | `Intel 80386` |

- Steps:
  1. `Checkout Code` using `actions/checkout` pinned to SHA `3d3c42e5aac5ba805825da76410c181273ba90b1` with comment `# v7.0.1` (`:49-53`).
  2. `Configure and build` (`:55-159`): a single `docker run --rm --platform linux/amd64` of `debian:bookworm-slim` mounting `${GITHUB_WORKSPACE}` at `/workspace` and passing `DEBIAN_ARCH`, `MULTIARCH_TRIPLET`, `TARGET_PLATFORM` (`:61-68`). All logic is an inline `bash -euxo pipefail -c '...'` script:
     - Selects the toolchain per platform via `case` (`:75-106`): native `build-essential` for x86_64; `gcc-/g++-<triplet>` + `libc6-dev-<arch>-cross` for the others; unsupported platform exits 1 (`:102-105`). Non-native builds `dpkg --add-architecture` (`:108-110`) and suffix target-library packages with `:<debian_arch>`.
     - Installs `ca-certificates cmake default-jre-headless file libssl-dev libusb-1.0-0-dev make pkg-config python3 tcl tcl-dev` plus toolchain (`:112-127`). Java JRE is needed for the HMServer jar / webui build steps (build deps defined in CMake, not in this module).
     - For cross builds sets `PKG_CONFIG_PATH=` and `PKG_CONFIG_LIBDIR` to the target multiarch dir (`:129-134`).
     - On x86_64 only, runs `python3 tests/test-components.py -v` (`:136-138`; test file `tests/test-components.py`, unittest running real CMake configure/build/install selections).
     - Resolves Tcl include/lib dirs via `pkg-config` and asserts `tcl.h` and `libtcl.so` exist (`:140-147`).
     - Configures with `cmake --preset "${TARGET_PLATFORM}"` and `-DDEPLOY_TO_REPO=OFF -DBUILD_TCL_MODULES=ON -DTCL_INCLUDE_PATH -DTCL_LIBRARY -DHAS_USB_SUPPORT=ON -DBUILD_WEBUI_AND_DEVICETYPES=ON` (`:149-155`), then `cmake --build --preset "${TARGET_PLATFORM}" --target package --parallel "$(nproc)"` (`:156-158`).
  3. `Verify staged package` (`:161-212`), runs on the host against `build/<platform>/rootfs`:
     - `test -s` for 20 artifacts (`:168-190`): binaries `bin/SetInterfaceClock crypttool eq3configcmd eq3configd hs485d hs485dLoader hss_led multimacd rfd ssdpd`; libs `libLanDeviceUtils.so libUnifiedLanComm.so libXmlRpc.so libelvutils.so libeq3config.so libhsscomm.so libxmlparser.so tclrega.so tclrpc.so`; `opt/HMServer/HMServer.jar`.
     - `file` on `bin/rfd` and `lib/tclrega.so` must contain the matrix `binary_format` string (`:192-197`).
     - Non-empty `www/webui/webui.js`, `www/webui/style.css`, `www/config/devdescr/DEVDB.tcl` (`:199-201`).
     - Count of `*.xml` in `src/devicetypes/rftypes` and `hs485types` must equal staged `firmware/rftypes` and `firmware/hs485types` counts (`:203-212`).
- No artifact upload, no caching, no release step: CI only validates that build and staging succeed.

### Observations
- Build runs inside a pinned Debian bookworm container (the runtime glibc baseline) even though the runner is Ubuntu 24.04; the host is used only for Docker and checks.
- The `Verify staged package` list hardcodes component names that must be kept in sync with `cmake/Components.cmake` staging.
- The webui prerequisite (Java) and `BUILD_WEBUI_AND_DEVICETYPES=ON` imply the webui/devicetype generation is exercised on all four platforms.

## update-prebuilt-libraries.yml

### Permissions and concurrency
- `permissions: contents: write, pull-requests: write` (`:20-22`).
- Concurrency group `update-prebuilt-libraries`, `cancel-in-progress: false` (`:24-26`).

### Job `regenerate` (`:28-118`)
- Runner `ubuntu-24.04`, 60 min timeout (`:31-32`).
- Header comment (`:1-5`) explains the rationale: libraries must be built in the same Debian bookworm environment as CI so they match the runtime glibc (a newer host would require e.g. `GLIBC_2.38`).
- Steps:
  1. `Checkout code`, same pinned `actions/checkout` SHA (`:35-37`); note: no `persist-credentials: false` here since the job pushes.
  2. `Build and deploy the compat libraries` (`:39-89`): `docker run` of `debian:bookworm-slim` (`--platform linux/amd64`) installing `cmake make g++ file` plus cross compilers for i686, aarch64, armhf (`:50-55`). Loops over `x86_64-linux-gnu i686-linux-gnu aarch64-linux-gnu arm-linux-gnueabihf` (`:57-61`):
     - configure with `cmake --preset <platform> -DDEPLOY_TO_REPO=ON -DBUILD_DEFAULT_COMPONENTS=OFF -DBUILD_TCL_MODULES=OFF -DBUILD_WEBUI_AND_DEVICETYPES=OFF` (`:69-73`; `DEPLOY_TO_REPO` copies into `lib/<platform>/`),
     - build target `compat-libraries` (`:74-76`; defined at `cmake/Components.cmake:49` as `DEPENDS xmlparser XmlRpc`),
     - `strip --unneeded` with per-arch strip binary (`:63-66`, `:78-80`), `chmod 0644`, `file` print (`:81-85`),
     - `rm -rf build` at the end (`:88`).
  3. `Restore file ownership`: `sudo chown -R "$(id -u):$(id -g)" lib` (`:91-92`), needed because the container ran as root.
  4. `Open a pull request if the libraries changed` (`:94-118`): `GH_TOKEN: ${{ github.token }}`; sets git identity to `Jens Maus <mail@jens-maus.de>` (`:98-99`); exits 0 if `git diff --quiet -- lib` (`:101-104`); otherwise creates branch `ci/regenerate-prebuilt-libs-${GITHUB_RUN_ID}`, commits `lib`, pushes, and `gh pr create --base main` with fixed title/body (`:106-118`).
- Outputs written to the repo: `lib/{x86_64-linux-gnu,i686-linux-gnu,aarch64-linux-gnu,arm-linux-gnueabihf}/libXmlRpc.so` and `libxmlparser.so` (the workflow only regenerates these two; the `lib/` tree holds four architecture directories with 10 tracked `.so` files each, 40 in total: libXmlRpc, libxmlparser, libelvutils, libhsscomm, libeq3config, libLanDeviceUtils, libUnifiedLanComm, tclrega, tclrpc, tclticks; the other eight per architecture have no visible regeneration path).

### Observations
- Potential self-trigger loop is avoided only because the PR merge changes `lib/` (not in the `paths` filter); pushes of the branch itself are not on `main`.
- The commit identity is a hardcoded personal name/email rather than a bot identity.
- The PR is created with `github.token`; PRs created by `GITHUB_TOKEN` do not trigger other workflows (such as `CI Build`) by default; no evidence in the file of a PAT or workaround.

## Migration-relevant notes

- All build logic is embedded in the YAML as inline Bash within a `docker run` string. A migration to another CI system needs: a bookworm container, four cross-toolchain setups, the pkg-config multiarch handling, and the post-build verification list.
- The two workflows duplicate the Docker/bookworm bootstrap pattern (platform loop vs matrix) with no shared composite action.
- Supply-chain posture: actions pinned by SHA, minimal permissions in `ci.yml`; Docker base image not digest-pinned; apt packages unpinned.
