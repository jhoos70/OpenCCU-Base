## Decisions

- **D001**: Q1 (existing-patterns) -> No, recommend best practices. Rejected: same pattern as current; provided references; organizational standards.
- **D002**: Q2 (service-architecture) -> Keep current architecture (refactor in place; CGI dispatcher plus Tcl executors, modular-monolith internals). Rejected: microservices; modular monolith as rebuild; serverless; event-driven as overall style. Clarified in-session: React SPA calls v1+v2 same-origin, v2 acts as in-process BFF, optional gateway is gated.
- **D003**: GQ1 (implementation-standards-gate) -> Use recommended best practices for refactor-in-place. Rejected: answer detailed questions.
- **D004**: Q3 (communication patterns) -> REST (synchronous) plus event bus / pub-sub. Rejected: gRPC; message queue; mixed.
- **D005**: Q4 (data storage) -> Keep current (unchanged); ReGaHss is system of record, no new store. Rejected: shared DB; polyglot; DB per service; event sourcing.
- **D006**: Q5 (data migration) -> Skipped, not applicable (no database; config rewrites become write-then-rename without format change).
- **D007**: Q6 (authentication/authorization) -> Keep current auth, hardened (ReGa session, 0/1/2/8 model, fail-closed, strict mode, CSPRNG sid). Rejected: JWT; OAuth 2.0/OIDC; API key; mTLS.
- **D008**: Q7 (cross-cutting) -> Logging/observability; API gateway/rate limiting; configuration management. Rejected: distributed tracing; circuit breakers; feature flags (hence no circuit breaker is specified in integration-contracts.json).
- **D009**: Q8 (deployment) -> Same as current (lighttpd CGI on OpenCCU rootfs). Rejected: Kubernetes; serverless; VM; PaaS.
- **D010**: Q9 (additional requirements) -> None, plan covers it.
- **D011**: Q10 (build) -> Keep CMake/Make plus OpenCCU packaging (auto-filled). Rejected: Maven; Gradle; npm; Go; pip.
- **D012**: Q11 (schema versioning) -> Not applicable, no relational DB (auto-filled). Rejected: Flyway; Liquibase; Sqitch.
- **D013**: Q12 (API development approach) -> Spec-first schema for v2; v1 schema derived from `methods.conf`; v1 behaviour unchanged (auto-filled). Rejected: code-first; manual; hybrid.
- **D014**: Q13 (data access) -> Keep current via ACL adapters, modernised incrementally (auto-filled). Rejected: ORM; query builder; micro-ORM.
- **D015**: Q14 (testing) -> Unit plus integration/contract testing (golden fixtures with mock bridges, fuzz, round-trip) in GitHub Actions (auto-filled). Rejected: E2E; performance suites (performance measured at the Phase 6 gate).
- **D016**: Q15 (logging) -> Structured syslog logging with correlation id (auto-filled). Rejected: APM; tracing; metrics stack.
- **D017**: CQ1 (confirmation) -> Accept all recommendations (Q10-Q15). Rejected: customize.
- **D018**: AQ1 (adaptive, performance) -> Skipped, trigger not met (performance not in focus_areas).
- **D019**: AQ2 (adaptive, data integrity) -> Skipped, trigger not met (data_integrity not in focus_areas).
- **D020**: AQ3 (module decomposition) -> Single deployable (modular monolith); the 10 components of Section 3 are internal layers. Rejected: separate/grouped services; per module.
- **D021**: AQ4 (adaptive, business rules) -> Skipped, trigger not met (no business-rule set above 10 in analysis).
- **D022**: AQ5 (integration layer) -> Anti-corruption layer per integration (one adapter per external system owns validation, escaping, error mapping, logging). Rejected: API gateway; ESB; direct point-to-point.
- **D023**: AQ6 (frontend-to-backend connectivity) -> Same-origin via reverse proxy (lighttpd serves SPA and `/api/*`, no CORS). Recorded in Section 5; no Section 2.3 row, no `internal_contracts[]` frontend entry. Rejected: separate origins with CORS; BFF; same as current.
- **D024**: AQ7 (frontend API base URL) -> Skipped, frontend not in `scope.include`; same-origin implies relative paths, so no `base_url_config` exists in the integration contracts.
- **D025** (post-approval amendment 2026-10-14, EG-3; extended by BD-16 on 2026-10-20: now 6 exact paths plus 2 existsFile patterns, createFile 4 paths): `CCU.existsFile` keeps level GUEST with an exact allow-list of 5 paths; `CCU.createFile` is ADMIN-only with a 2-path allow-list. Rejects ADMIN-only existsFile (would break classic UI callers).
- **D026** (post-approval amendment 2026-10-14, EG-17): sid >= 128 bits is relaxed; ids minted by this feature use /dev/urandom at the maximum of the compatible 12-character format (~59.5 bits, 62^10); ReGa-issued ids unchanged; brute force mitigated by per-sid/per-IP rate limiting. Rate limiting is OPT-IN (user decision 2026-10-14, flag `rate_limit`, default false, so v1 default behaviour stays identical for the classic UI): the brute-force mitigation is therefore active only when `rate_limit` is on or in strict/v2 mode, never under the default configuration. Optional v2 128-bit cookie token is a follow-up outside this scope.
- **D027** (deferred user decision 2026-10-14, EG-1; resolved by BD-17 on 2026-10-20: keep the safe default, no removal now): backup CGIs default to ADMIN + empty path allow-list + fail-closed session check; removal (404) only after the caller check passes (lighttpd mapping and OpenCCU patch callers). Carried as a gated task, not a blocker.

## Blueprint decisions (lock the provisional values; no architecture decision is changed)

Authority for every value: `contracts/integration-contracts.json` -> `locked_values`. Each is flagged `locked_by: blueprint`
so the tasks phase can refer to a literal instead of the word "provisional".

- **BD-01** (EG-12) Strict-mode violation on v1: JSON-RPC error code 405, message `strict mode: Content-Type application/json and X-Requested-With required`, HTTP 200 (v1 envelope kept). On v2: HTTP 415 for a wrong Content-Type, HTTP 403 for a missing/empty `X-Requested-With`; body still carries the envelope with code 405. Body is not parsed and no method script is sourced.
- **BD-02** (EG-12) Validation error: code 403, message `invalid argument (<name>)`, v2 HTTP 422. Introduced code 403 is added to the code space; 101, 201-203, 300 stay unused.
- **BD-03** (EG-12) Path-not-allowed: code 500, message `path not allowed`, v2 HTTP 403 with `error.reason = PATH_NOT_ALLOWED`. Name-already-exists: code 500, message `name already exists (<name>)`, v2 HTTP 409 with `error.reason = NAME_EXISTS`. Because code 500 is overloaded in v1, the v2 mapping uses the optional additive field `error.reason`.
- **BD-04** (EG-12) v2 HTTP status mapping: 100/102/103 -> 400; no/invalid sid (fail-closed upl 0) -> 401; sid valid but upl below LEVEL (code 400) -> 403; code 401 -> 404; 402 and 403 -> 422; 405 -> 415 or 403 (BD-01); 200 and unreserved 500 -> 500; 501-507, 599, 601-604 -> 502; `Session.login` refinement: 501 -> 401, 503 -> 503; batch limit -> 413; per-sid limit -> 429 with `Retry-After`; wrong HTTP verb -> 405 with `Allow`. The JSON-RPC error envelope is always present in the body.
- **BD-05** (EG-12) Headers: sid `X-Session-Id` (wins over `params._session_id_` and the cookie; mismatch is logged); anti-CSRF `X-Requested-With` (any non-empty value, clients send `XMLHttpRequest`); response `X-Correlation-Id` on every response; `Retry-After` (seconds) on 429. Cookie (opt-in `cookie_mode`): name `hm_sid`, attributes `HttpOnly; SameSite=Strict; Path=/api`, plus `Secure` when `HTTPS` is set in the CGI environment, no `Max-Age` (session cookie, ReGa timeout 900 s applies).
- **BD-06** (EG-12) Correlation id: 16 lowercase hex characters (8 bytes from /dev/urandom), regex `^[0-9a-f]{16}$`; error text `internal error (ref: <id>)`; syslog line via `logger -t webui-api -p daemon.err` as `cid=<id> method=<name> uid=<uid|-> code=<code> errorInfo=<single line, newlines escaped as \n>`.
- **BD-07** (EG-12) Access-denied text: `access denied ("<LEVEL>" needed, session level <upl>)`, with upl 0 for a missing/unknown session.
- **BD-08** (EG-12) Configuration: one Tcl-readable file `src/webui/www/api/apiconfig.conf` (`array set API_CONFIG {...}`), flags `strict_mode`, `config_tool_mode`, `v2_enabled`, `cookie_mode`, `rate_limit` (opt-in per user decision 2026-10-14: enables the per-IP `Session.login` limiter and the per-sid request limiter on v1; both are always enforced on /api/v2 and when `strict_mode` is true), `sid_shape_strict` (EG-8 gated sid shape validator; the flag referenced by the sid-shape tasks T116/T117) (all default `false`), `allowed_origin` (default absent -> no `Access-Control-*`); numeric keys in BD-09. Defaults preserve v1 (NFR-045), in particular `rate_limit=false` means no 429 can occur on the v1 path; every flag switchable without redeploy (NFR-054).
- **BD-09** (EG-13, EG-4, EG-10) Limits: `batch_limit` 20 elements; `per_sid_limit` 60 requests per `per_sid_window_seconds` 10; `login_ip_limit` 10 `Session.login` attempts per `login_ip_window_seconds` 60 (per-IP part of EG-17 mitigation; client IP from REMOTE_ADDR; enforced only when `rate_limit` is on or in strict/v2 mode); `model_default_limit` 100, `model_max_limit` 500; `long_poll_default_seconds` 25, `long_poll_max_seconds` 55; `event_lock_stale_seconds` 10; `download_timeout_seconds` 300 (EG-4 provisional value confirmed; the CGI never blocks beyond timeout + 5 s). `EVENT_LIMIT` stays 64.
- **BD-10** (EG-12) Validator patterns: sid `^@?[A-Za-z0-9]{10}@?$` (gated by EG-8 until runtime-traced); serial and lgwserial `^[A-Za-z0-9_-]{1,32}$`; LAN gateway key `^[0-9A-Fa-f]{32}$`; language `^[a-z]{2}$`; dataId `^[A-Za-z0-9_.-]{1,64}$`; tweak key `^[A-Za-z0-9_.-]{1,64}$`; testId `^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}$`; correlation id `^[0-9a-f]{16}$`; control characters U+0000-U+001F except tab, LF, CR rejected in every string parameter.
- **BD-11** (EG-5) v2 profile: attributes `userId`, `userName`, `firstName`, `hasPassword`, `isNoExpert`, `language` (the former `reGaVersion` attribute was dropped by BD-15); the language file key is the ReGa `UserFirstName` for both read and write (the only key `User.getLanguage` reads today; `User.setLanguage` keeps its v1 `userName` key, frozen); no ReGa-version attribute or whitelist (removed with the upstream ReGa version methods, BD-15); GET: GUEST or higher reads own profile, `?userId=` only for ADMIN; PUT: USER or higher writes own `language`, ADMIN may write another user's profile. Residual: key choice to be confirmed against OpenCCU-patch callers (no in-repo caller of User.getLanguage/setLanguage exists).
- **BD-12** (EG-13) Event payload: `{type:"datapoint.changed", data:{address, datapoint, value}}` (value as string); long-poll parameter `timeout` in seconds; the producer mechanism stays gated by EG-2.
- **BD-13** (EG-13) `/api/v2/model` query: `sections` (comma list of devices, channels, rooms, functions, sysvars, programs, datapoints; default all but datapoints), `limit`, `offset`; every section is `{total, offset, limit, items}`.
- **BD-14** (EG-13) Rate limit and batch rejections (rate limits are opt-in via `rate_limit`, default false; always enforced on /api/v2 and in strict mode): per-sid overflow (61st request within 10 s) and per-IP login overflow (11th `Session.login` within 60 s) return JSON-RPC error 429 `rate limit exceeded` (HTTP 200 on v1, HTTP 429 plus `Retry-After` on v2) without sourcing any method script; a v2 batch over `batch_limit` is rejected before execution with HTTP 413 and error 403 `invalid argument (batch)`; v1 has no batch.
- **BD-15** (re-baseline, 2026-10-20) The legacy API tree moved upstream; the user decided to stay on the current branch and re-baseline all SDD artifacts to HEAD 1651075b (diff of src/webui/www/api and src/webui/www/tcl against 030dba79): methods.conf now has 179 methods (20 namespaces); upstream #193 removed `User.getReGaVersion` and `User.setReGaVersion` (and their scripts), so the v2 profile loses `reGaVersion` and the unauthenticated allow-list shrinks to 8 methods (NONE 8 / GUEST 48 / USER 30 / ADMIN 93 after the deliberate changes); upstream #194 added `RecoveryMode.enter` (ADMIN, fixed-purpose exec/file writer: PLATFORM from /VERSION, 500/501 errors, `rega system.Save()`, flag file /usr/local/.recoveryMode, background `/sbin/reboot -d 2`), covered as an additional acceptance set under SP034 (component system-admin, no new SP id); upstream #202 moved `backup/version.cgi` to /VERSION (LF-encoded) and added `get_platform` to tcl/eq3_old/common.tcl (SP011, SP014). No architecture decision changed; the amendment is recorded in the ADR Approval Notes.
- **BD-16** (user decision A, 2026-10-20, EG-3 corrected) The earlier caller search was incomplete. Verified callers in src/webui/www_source and opt/HMServer/pages need `CCU.existsFile` (LEVEL stays GUEST) exact paths `/etc/config/userAckSecurityHint`, `/etc/config/firewallConfigured`, `/etc/config/fieldTestActive` (homematic.com.js:98, startpage.js:69, functions.js:4074/4078, StorageSettingsDialog.ftl:401), `/etc/config/showDiagramDatapoints`, `/media/sd-mmcblk0/measurement`, `/etc/config/legacyAPIMigrationAccepted` (webui.js:296, inside a commented-out block, kept) plus two anchored patterns for the per-user ack files built dynamically in webui.js:353/359: `^/etc/config/userprofiles/userAckInstallWizardId_[0-9]{1,10}$` and `^/etc/config/userprofiles/userAckInstallWizard_[^/\x00]{1,200}$` (the name part comes from toAckName, which strips '/'; the prefix is fixed and '/' is excluded, so no traversal is possible). `CCU.createFile` (ADMIN) exact paths: `/etc/config/userAckSecurityHint`, `/etc/config/firewallConfigured`, `/etc/config/fieldTestActive` (functions.js:4075 activateDeviceBetaFw), `/etc/config/legacyAPIMigrationAccepted`; the earlier statement "no in-repo consumer of createFile" is withdrawn. Patterns apply to existsFile only. Rejected: widening to a prefix glob (traversal risk), ADMIN-only existsFile (breaks classic UI). Authority: `contracts/integration-contracts.json` -> `locked_values.path_allow_lists`.
- **BD-17** (user decision B, 2026-10-20, EG-1 resolved: safe default) Keep the backup CGIs (binfile/textfile/tarfile/run-script/links/paramset/login/logout) at ADMIN + empty path allow-list + fail-closed; NOT removed now; deprecation is announced, removal in a later release. Evidence: lighttpd in OpenCCU buildroot-external/overlay/base/etc/lighttpd maps .cgi to tclsh, /api/ is not proxied away and nothing denies /api/backup/, so they are reachable; no callers found in OpenCCU-Base or OpenCCU (rfd-config appears only as a comment); third-party tools unknown. T110 (removal branch) is deferred by decision; T109 (caller check) is covered by this research evidence. Rejected: removal now (unknown third-party callers).
- **BD-18** (user decision C, 2026-10-20, OpenCCU packaging patches stay downstream) The OpenCCU rootfs-patches (buildroot-external/package/openccu-base/rootfs-patches/*.patch) are applied to the Base rootfs at image build. 13 patches touch www/api or www/tcl files (0001, 0031, 0038, 0044, 0054, 0057, 0104, 0109, 0131, 0163, 0164, 0203, 0205; 14 files, derived from the '--- a/www/(api|tcl)/' headers). A coordinator test applied them in order: legacy tree 13/13 OK, staged tree only 3/13 OK, because 208 of 210 overlapping staged files were rewritten (new headers, pasted per-script admin_audit helper, LF instead of CRLF, methods.conf UTF-8 instead of ISO-8859-1). New rule (NFR-056): (1) a staged file whose v1 behaviour is unchanged is a verbatim copy of the legacy source (byte-identical, CRLF and ISO-8859-1 kept); (2) files with intentional behaviour change are minimal edits preserving line endings, encoding and untouched context lines, and shared helpers (admin_audit etc.) live in one eq3 library, not pasted per script; (3) the 14 patch-touched files keep the 13 patches applying, except documented conflicts listed in COPY-PLAN.md as "patch N must be regenerated at the next Base bump" (expected: downloadFirmware.tcl and user/*hmipserver.tcl exec hardening, methods.conf where registry edits collide); (4) a schema-harness patch-apply gate (env OPENCCU_PATCH_DIR, default ~/dev/OpenCCU/buildroot-external/package/openccu-base/rootfs-patches, skipped when absent) applies the patches in order to a composed staged tree (legacy www/api + www/tcl overlaid with the staged components, mapping eq3_old/* and eq3/{session,rega}.tcl to www/tcl) and reports per-patch OK/FAIL; target 13/13 minus the documented conflicts. Rejected: moving the patches into Base now (downstream concern); regenerating all patches.

## Evidence-gap handling (no decision taken)

- **User decision (rate limits, 2026-10-14)**: rate limiting is an OPT-IN config flag, default OFF for v1 (`rate_limit=false`), so v1 default behaviour stays identical for the classic UI (constraints.unchanged, NFR-045). Consequence recorded for EG-17/D026/NFR-043: the brute-force mitigation is active only when `rate_limit` is on or in strict/v2 mode. Open detail EG-26 (empty `REMOTE_ADDR`, batch counting) carries a blueprint default that the user should confirm.
